# Lessons for KOML

Messy client descriptions often combine pain, environment, desired behavior and success criteria. A deterministic parser can separate explicitly tagged facts and retain their evidence, but cannot infer the client's intended scope from prose without exceeding this project's honesty boundary.

Validated assumption: the planted section-presence rules produce exact counts and exact issue sets on 200 synthetic records. A mutation test changes an explicit description and changes the figures, proving computation rather than a static fixture report. This does not validate usefulness or accuracy on Henry's real client conversations. That assumption remains untested until the two-week trial.

Evidence-based build improvement: report rendering recomputes from saved original descriptions rather than trusting cached summary counts. A regression test corrupts cached counts and verifies that the report still reflects explicit evidence. This protects the trust boundary of reported figures.

Operating rule: preserve source statements and line references before adding automation; separate measured fixture correctness from unmeasured real-world value.
